# 团队进度查询协议（模板）

本文件是进度查询机制的唯一真相源。由 `ct1` skill 部署到项目，部署时把"默认团队配置"替换为实际组建的非 leader 成员。

## 触发词

用户发送以下任一短语，主线程启动一次**进度同步**：

- 中文：`进度` / `查进度` / `进度如何` / `同步进度`
- 英文：`status` / `progress` / `check progress` / `where are we` / `how's it going`

## 查询流程（主线程执行）

1. 识别触发词
2. **并行**向以下非 leader 成员发送「状态请求模板」（同一消息多个 `SendMessage`，避免串行）
3. 收集回复，按「汇总表格格式」整理为 Markdown 表格
4. 超时未回复者对应行显示 `⏳ 未响应`，表后提示"可再次发送触发词重新查询"

## 团队成员（部署时替换为实际活跃角色）

进度查询的成员范围（不含 leader）。成员列表由实际活跃角色生成，不再硬编码前端/后端/测试/reviewer：

> 部署时替换为本次实际组建的非 leader 成员（如 `frontend-dev`、`backend-dev`、`tester`、`reviewer`、`migration-specialist` 等）。

## 状态请求模板（发给每位执行者）

所有角色统一使用 **StatusReport/v2**（11 字段）。完整 schema 见 `references/status-report-schema.md`。

```
请按 StatusReport/v2 格式报告你当前的状态：
【协议版本】StatusReport/v2
【任务ID】任务板中的唯一 ID
【状态】空闲 / 就绪 / 工作中 / 阻塞 / 审查中 / 测试中 / 完成
【当前任务】一句话描述
【进展】已经完成的可验证结果
【阻塞项】无 / 问题或依赖 ID
【下一步】下一个具体动作
【需要的输入】无 / 所需输入
【触发事件】无 / 设计完成 / 契约就绪 / 可审查 / 可测试 / 待验收
【待答复问题】无 / 当前卡点的问题
【变更文件】无 / 本轮新增或修改的文件列表
【验证结果】未执行 / 命令、结果和限制
```

问题升级循环的完整规范（子 agent 问题记录、触发事件检查点、leader 聚合与答复分发）见 `references/question-escalation-protocol.md`。审查循环的完整规范（reviewer 角色、审查报告、风险驱动审查）见 `references/code-review-protocol.md`。

## 汇总表格格式

```
| 成员 | 状态 | 任务ID | 当前任务 | 进展 | 阻塞项 | 下一步 | 触发事件 | 待答复问题 | 变更文件 | 验证结果 |
|---|---|---|---|---|---|---|---|---|---|---|
```

> 列和行随实际团队角色调整。成员列用"emoji + 角色名"标识。

## 执行者回复规范

执行者收到状态请求后，**严格按 StatusReport/v2、固定顺序**回复，不额外寒暄，便于主线程解析。

### 无疑问时的示例

```
【协议版本】StatusReport/v2
【任务ID】BE-003
【状态】空闲
【当前任务】等待分配需求
【进展】—
【阻塞项】无
【下一步】待 leader 派发任务
【需要的输入】首个需求描述
【触发事件】无
【待答复问题】无
【变更文件】无
【验证结果】未执行
```

### 在触发事件节点遇到问题时的示例

```
【协议版本】StatusReport/v2
【任务ID】FE-001
【状态】工作中
【当前任务】前端登录模块开发
【进展】完成页面骨架与状态管理
【阻塞项】无
【下一步】等待答复后决定登录态实现方案，继续实现登录表单
【需要的输入】无
【触发事件】可审查
【待答复问题】
1. [Q-FE-001][可审查] 是否采用方案A（JWT+refresh token）或方案B（session）实现登录态？ (关联任务: 前端登录模块)
2. [Q-FE-002][可审查] 表单验证错误提示文案是否沿用旧版？ (关联任务: 前端登录模块)
【变更文件】
- src/components/LoginForm.vue（新增）
- src/store/user.js（修改）
【验证结果】未执行
```

**问题 ID 格式**：`Q-{role}-{seq}`（如 `Q-FE-001`、`Q-BE-001`），seq 按 agent 自增。

### 触发事件节点行为

执行者在触发事件节点（详见 `references/question-escalation-protocol.md`）把所有「待上报」问题标记为「已上报」并填入【待答复问题】，同时填写【变更文件】供审查。**不暂停工作**：遇到问题先跳过该部分继续推进其他工作，等答复到达后回填。

### reviewer 状态示例

reviewer 不参与编码，其状态为 空闲/审查中/完成：

```
【协议版本】StatusReport/v2
【任务ID】FE-001
【状态】审查中
【当前任务】审查 frontend-dev 的登录模块代码
【进展】—
【阻塞项】无
【下一步】输出 Code Review 报告
【需要的输入】无
【触发事件】无
【待答复问题】无
【变更文件】src/components/LoginForm.vue, src/store/user.js
【验证结果】未执行
```

审查循环的完整规范（reviewer 角色定义、审查报告 schema、leader 分流、风险驱动审查）见 `references/code-review-protocol.md`。

## leader 聚合展示格式

主线程收集回复后，**同一条消息**内分两个 section 展示给用户：

```
📊 团队进度报告 · {时间}

## 一、进度总览
| 角色 | 状态 | 任务ID | 当前任务 | 进展 | 阻塞项 | 下一步 | 触发事件 | 待答复问题 | 变更文件 | 验证结果 |
|------|------|--------|----------|------|--------|--------|----------|------------|----------|----------|
| 🖥️ 前端 | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... |
| ⚙️ 后端 | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... |
| 🧪 测试 | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... |

## 二、待答复问题（共 N 题）
| 编号 | 来源 | 触发事件 | 问题 | 关联任务 | 提出次数 |
|------|------|----------|------|----------|----------|
| Q-FE-001 | frontend-dev | 可审查 | ... | ... | 1 |
| Q-BE-001 | backend-dev | 可审查 | ... | ... | 1 |

请回答上述问题。可部分回答，格式如「Q-FE-001: 方案A」；跳过的题目将保留至下次询问。
```

**展示规则**：
- 表格列随实际团队角色变化
- 「待答复问题」section 仅当任一成员有非「无」的问题时出现，否则不显示
- leader 对跨 agent 的相似问题做语义去重（合并来源），重复问题通知来源 agent 作废
- 用户回答后，leader 通过 `[CONTEXT ADDENDUM]`（来源=用户答复）分发给对应 agent（详见 `references/question-escalation-protocol.md`）

## 协议复用说明

本文件是进度查询机制的唯一真相源。主线程识别到触发词后，按本文件规定的模板和流程执行，不依赖临时记忆。会话重建后，通过项目记忆导航 → 本文件恢复机制。
