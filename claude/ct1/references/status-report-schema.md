# StatusReport/v2（状态报告协议）

## 是什么

所有角色（leader、执行者、tester、reviewer、专项角色）状态报告的**唯一真相源**。统一了过去混用的 6/8/9 字段模板，使主线程、leader 和执行者使用同一格式，状态能关联任务、代码、问题和验证结果。

## 协议版本与兼容性

- 当前版本：`StatusReport/v2`
- 项目运行目录记录协议版本，不复制全部 Skill 内容
- 版本检查规则（恢复旧项目时）：
  - `v1`（旧 6/8/9 字段）：提示或自动迁移到 v2
  - `v2`：直接使用
  - 未知版本：停止自动覆盖，报告给用户

## Schema（11 字段，固定顺序）

```
【协议版本】StatusReport/v2
【任务ID】任务板中的唯一 ID（如 BE-003；未入任务板时填"—"）
【状态】空闲 / 就绪 / 工作中 / 阻塞 / 审查中 / 测试中 / 完成
【当前任务】一句话描述
【进展】已经完成的可验证结果（非主观百分比）
【阻塞项】无 / 问题或依赖 ID
【下一步】下一个具体动作
【需要的输入】无 / 所需输入
【触发事件】无 / 设计完成 / 契约就绪 / 可审查 / 可测试 / 待验收
【待答复问题】无 / 问题列表
【变更文件】无 / 文件路径列表
【验证结果】未执行 / 命令、结果和限制
```

### 字段含义

| 字段 | 用途 |
|---|---|
| `协议版本` | 协议迁移与兼容性判断 |
| `任务ID` | 关联任务板，使进度可追溯到具体任务 |
| `状态` | 当前工作状态（见状态枚举） |
| `当前任务` | 一句话描述 |
| `进展` | **可验证结果**，禁止仅用主观百分比 |
| `阻塞项` | 无 / 具体问题或依赖 ID |
| `下一步` | 下一个具体动作 |
| `需要的输入` | 推进所需输入 |
| `触发事件` | 驱动下一阶段的事件（见触发事件枚举） |
| `待答复问题` | 需用户/leader 决策的问题（格式见 `references/question-escalation-protocol.md`） |
| `变更文件` | 本轮新增/修改的文件路径（供审查与 ownership 校验） |
| `验证结果` | 命令、输出、限制；无验证时填"未执行" |

### 状态枚举

`空闲 / 就绪 / 工作中 / 阻塞 / 审查中 / 测试中 / 完成`

### 触发事件枚举

`设计完成 / 契约就绪 / 可审查 / 可测试 / 待验收`

## 各角色用法

### 执行者（frontend-dev / backend-dev / fullstack-dev 等）

按 11 字段完整回复。里程碑节点必须填写 `触发事件`、`待答复问题`、`变更文件`。

### reviewer

状态为 `空闲 / 审查中 / 完成`。`任务ID` 填被审查的任务 ID，`变更文件` 填审查范围。

### tester

状态为 `空闲 / 工作中 / 完成`。`验证结果` 填真实测试命令与输出。

### leader

leader 是编排者，不执行开发任务。需要汇报时，`状态` 填 `工作中/空闲`，`当前任务` 填当前编排动作。

## 缺少必填字段

缺少必填字段时，主线程应标记报告为**不完整**，要求补充，不擅自补全。
