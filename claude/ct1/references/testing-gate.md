# Testing Gate（测试门禁）

## 是什么

tester 从"编写用例"升级为**质量负责人**：审查 AC 可测性、制定测试计划、建立 AC-测试映射、执行测试、建立缺陷并跟踪复测、给出是否允许交付的质量结论。

## tester 职责

1. 审查验收标准是否可测
2. 制定测试计划
3. 建立 AC 到测试用例的映射
4. 检查开发自测证据
5. 执行或指导执行自动化、集成、边界和回归测试
6. 建立缺陷并跟踪复测
7. 给出是否允许交付的质量结论
8. 执行冷启动走查：在干净环境中以 fresh user 身份逐步执行用户旅程，记录每步是否通过

> **边界**：tester 验证规格、功能、回归、环境和系统行为，**不单独定义目标用户和产品方向**（那是 user advocate 的职责）。tester 通过不能自动替代 user value 通过。详见 `references/user-value-gate.md`。

## tester 启动阶段

| 阶段 | 时机 | 动作 |
|---|---|---|
| 计划期 | Requirement Brief 完成后 | 审查 AC 可测性、制定测试计划、建立 AC-测试映射 |
| 执行期 | 出现 `test-ready` 交付物后 | 执行测试、建立缺陷、跟踪复测、给出质量结论 |

## 缺陷状态机

```
open
  → assigned
  → fixed
  → retest
  → closed

复测失败进入 reopened。
```

## 测试门禁

| 门禁 | 要求 |
|---|---|
| AC 覆盖 | 每个必需 AC 至少有一个测试 |
| 缺陷 | P0/P1 缺陷为零 |
| 执行 | 必需测试全部执行 |
| 记录 | 测试命令、结果和环境已记录 |
| 未执行说明 | 未执行测试必须说明原因和风险 |
| 环境 | 环境不可用不得标记为"测试通过" |
| 用户旅程跑通 | 冷启动走查全部步骤通过；任一步骤失败则阻断交付（即使所有 AC 通过、P0/P1=0） |

## 验收标准

- tester 提供真实测试结果，而不只是建议
- 测试失败能退回对应开发任务
- 修复后有复测记录
- 最终交付引用 TEST_REPORT
- 冷启动走查结果记入 TEST_REPORT，作为交付门「用户旅程跑通」的引用证据
